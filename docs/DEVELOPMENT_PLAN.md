## 里程碑与范围控制

- M1：D1 工程准备可追踪；Python 搜索能力作为环境限制单列，不伪称通过。
- M2：D4 最小可信底图与路线数据，未核实的内容不混入正式展示。
- M3：D7 核心地图闭环通过，是最优先里程碑。
- M4：D12 功能与内容冻结；D13—14 专注报告、回归和交付。

P0 优先；若 D7 核心联动延期，先取消 P2 单部队独立模式并简化非必要滚动效果，再提出 P1 内容规模调整。不得为了赶进度合并各部队的历史路线，或省略来源说明。

## 每日工作节奏

开始：阅读相关文档、检查 Git 状态、领取任务编号。完成：运行对应测试、记录实测证据和限制、更新任务看板、提交本模块。新阶段的设计和历史范围决策有争议时记录候选与取舍，由用户确认后固化。

报告素材从 D3 开始随做随存：设计草图、关键实现截图、核心算法说明、测试和优化前后结果；D13 负责整理而非补造记录。

## 主要风险

| 风险 | 触发条件 | 处理与时间点 |
| --- | --- | --- |
| 史料不足 | D4 仍无法核实路线节点 | 缩小到有依据的节点级展示，明确缺口；与用户确认覆盖范围 |
| 动画冲突 | 同一属性被多个库修改、重复时钟 | D5/9 查生命周期；保留单一所有者，关闭可选动画层 |
| 地图性能 | 拖动明显卡顿或低于目标 | D7/11 预计算、按段更新、简化底图，暂停装饰效果 |
| 素材权限 | 图片许可未知或来源失效 | D3/12 更换为有依据可用素材，保留文字展陈，不冒充授权 |
| 环境 | Python 不可用或安装源访问失败 | 文档保留离线可读；后续由用户决定 Python 安装或跳过搜索脚本 |
| 课程要求缺失 | 报告模板/字数/提交方式未给出 | D3 前补充最佳；D13 前必须明确排版与交付形式 |
