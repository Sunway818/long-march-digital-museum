## 响应式与浏览器矩阵

桌面检查 1280×720、1440×900；平板 768×1024；移动 360×800、390×844。地图/面板支持横竖屏调整。检查标题换行、地图图例、控制条、详情溢出、触摸命中区和页面级横向滚动。

Chrome、Edge、Firefox 使用测试日可用稳定版，Safari/iOS Safari 尽量实机验证；未具备设备只标“未测”，模拟尺寸不能冒充实机兼容。记录操作系统、浏览器完整版本、视口、设备和测试提交。

## 性能方法与预算

第 11 天固定构建产物、本机/部署地址、浏览器、CPU 和网络限速设置。移动 Lighthouse 同一设置跑 3 次取中位数，保留原报告。LCP≤2.5s、CLS≤0.1、TBT≤200ms 为实验室目标；真实 INP 需 field 数据，不以 Lighthouse 分数代替真实用户结果。

候选资源预算：初次静态主图≤500KB、首屏所需传输≤1.5MB、初始 JS gzip≤250KB（地图分包另计）；第 3/4 天依据实测调整并记录理由。不要为达预算损害文字和史料可读性。

DevTools 录制地图连续拖动 10 秒，观察帧率、长任务和输入反馈；目标 50–60fps，持续低于 30fps 必须降低效果或数据粒度。检查内存与动画清理，重复进入模块至少 10 次。每项结果附设备和版本，当前不填虚构数值。

## 缺陷与证据记录

记录格式：测试 ID、需求 ID、时间、执行者、提交、环境、前置条件、步骤、预期、实际、结果（通过/失败/阻塞/未测）、截图/报告路径、缺陷 ID、修复提交和回归结果。

阻断：无法启动/核心地图无法使用/正式史料错误；严重：关键交互或键盘访问失效；一般：非阻断显示或性能问题；轻微：局部视觉细节。D12 前清除阻断与严重问题，剩余问题明确告知并判断是否影响验收。

每完成模块运行相关检查；新增失败或改动触发针对性回归。D14 从新目录按 README 清洁安装、构建、预览与核心路径回归，不能只验证开发服务器。
